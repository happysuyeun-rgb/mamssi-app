## 1. 새로 두면 좋은 문서

### 1.1 날짜·타임존 규칙 (로직 정의서)

**이유:** "오늘", 주간 달력, 30일 정원, 오늘 기록 여부 등에서 **로컬 날짜**를 쓰도록 수정했으나, 문서화되어 있지 않음. 유지보수·버그 수정 시 혼란 방지를 위해 한곳에 정리해 두는 것이 좋음.

**포함 권장 내용:**

| 구분 | 규칙 | 참고 위치 |
|------|------|-----------|
| "오늘" 날짜 | `formatIso(new Date())` 또는 `getFullYear/getMonth/getDate` 기반 로컬 YYYY-MM-DD 사용. `toISOString().split('T')[0]` 사용 금지(UTC라 타임존에서 하루 어긋남). | Home `todayIso`, hasTodayEmotion, TodayRecordCTA |
| 주간 달력 슬롯 날짜 | `getDayIso(weekStart, index)` 등에서 **로컬** YYYY-MM-DD 반환 (`toLocalIsoDate` 사용). | WeeklyMoodWidget |
| 30일 정원 기록일 수 | `emotion_date` 우선, 없으면 `created_at`을 **로컬** 날짜로 변환해 유일 날짜 집합 계산. | Home `garden` |
| 오늘 기록 여부(버튼/모달) | `hasTodayEmotion(todayIso)`로 **로컬 오늘** 구간(자정~23:59:59.999) 쿼리. | useEmotions, Home |

**문서명 예:** `docs/DATE_AND_TIMEZONE_RULES.md`

### 1.2 홈·감정 기록 CTA 동작 정리 (설계/UX)

**이유:** CTA 문구 고정, 나만보기 완료 시 모달 등 동작이 코드에만 있어, 기획/디자인 검토나 추후 변경 시 참고할 문서가 없음.

**포함 권장 내용:**

- 메인 버튼 문구: 항상 **"오늘의 감정 기록하기"** (기록 여부와 무관).
- 버튼 클릭 시:
  - **오늘 나만보기 기록이 이미 있음** → 모달: "이미 오늘의 감정을 기록하였어요! 공개 감정을 기록하시겠어요?" [아니오] [예]
    - 예 → 감정 기록 화면(`/record?date=오늘`)으로 이동.
    - 아니오 → 모달만 닫기.
  - 그 외 → 바로 감정 기록 화면으로 이동.
- "오늘 나만보기 기록 있음" 정의: `emotion_date === 오늘(로컬)` 이고 `is_public !== true` 인 기록이 1건 이상.

**문서명 예:** `docs/HOME_CTA_AND_RECORD_FLOW.md` 또는 기존 UX/플로우 문서에 섹션 추가.

---

### 1.3 감정 단건 삭제 시 게이지 동작 (설계 결정)

**이유:** "감정 기록 삭제 시 게이지가 어떻게 되나요?"에 대한 현재 구현이 문서로 없음. 전부 삭제 시 초기화는 `EMOTION_RECORDS_EXPORT_AND_DELETE_PLAN.md`에 있으나, **단건 삭제**는 별도 정리 필요.

**포함 권장 내용:**

- **현재 동작:** 감정 기록을 **한 건 삭제**해도 `flowers.growth_percent`는 **변경하지 않음**. 게이지/성장치는 유지.
- **이유(선택):** 구현 단순성, "삭제 = 포인트 회수" 정책 미적용.
- **추후 옵션:** 삭제 시 해당 기록이 공개였으면 −10pt, 비공개였으면 −5pt 반영(또는 해당 날짜 기준 재계산) 등은 별도 설계 후 반영 가능.

**문서명 예:** `docs/FLOWERS_DESIGN_2026-03-16.md`의 "감정 삭제와 성장" 섹션 추가, 또는 `docs/EMOTION_DELETE_AND_GAUGE.md` 단일 문서.

  - **감정 단건 삭제와 게이지:** 위 1.3과 동일 내용을 본 문서에 짧게라도 명시.

- **현재:** 전부 삭제 시 emotions 삭제 + 꽃 초기화, 구현 순서, 참고 파일까지 잘 정리됨.
