# 안드로이드 스토어 제출 직전 체크리스트 (마음,씨)

정식 공개 전에 "출시 가능" 여부를 빠르게 판단하기 위한 1페이지 체크리스트입니다.

---

## AI/자동 검증 가능 항목 (제가 해줄 수 있는 것)

아래는 코드/스크립트로 검증 가능하므로, 필요 시 **"자동 검증 실행해줘"**라고 요청하면 됩니다.

| 항목 | 명령 | 제가 할 수 있는 것 |
|------|------|-------------------|
| 타입 체크 | `npm run typecheck` | 실행 후 통과/실패 보고 |
| 빌드 | `npm run build` | 실행 후 통과/실패 보고 |
| 린트 | `npm run lint` | 실행 후 에러 개수 보고, 필요 시 일부 자동 수정 |
| 테스트 | `npm run test:ci` | 실행 후 실패 목록 보고, **실패 원인 분석 및 수정 시도** (목/환경 이슈 시 설명만) |
| 전체 검증 | `npm run verify` | lint → typecheck → format → test:ci → build 한 번에 실행 |
| 개인정보/약관/문의 | 코드 검색 | 앱 내 노출 위치·문의 이메일 존재 여부 확인 |

**수동만 가능한 항목** (제가 대신할 수 없음): 실기기 크래시 체크, 실제 로그인/결제 플로우, 네트워크 끊김 UX, 스토어 스크린샷·설명 문안 작성, 콘텐츠 등급 설문.

## 1) P0 (출시 차단 항목)

아래는 하나라도 실패하면 출시를 보류해야 합니다.

| 항목 | 확인 방법 | 기준 | 상태 |
|------|-----------|------|------|
| 빌드 성공 | `npm run build` | 에러 0 | ☐ |
| 타입 체크 | `npm run typecheck` | 에러 0 | ☐ |
| 핵심 플로우 수동 테스트 | 아래 "핵심 시나리오" 8개 | 전부 통과 | ☐ |
| 로그인/회원가입 동작 | 구글/애플(사용 중인 provider) | 실패율 0% | ☐ |
| 기록 작성/수정/삭제 | 텍스트, 이미지 포함 | 데이터 정합성 이상 없음 | ☐ |
| 공감숲 조회/공감/신고/삭제 | 목록/상세 모두 확인 | 런타임 에러 없음 | ☐ |
| 오프라인/네트워크 예외 UX | 비행기모드/불안정망 | 사용자 안내 문구 정상 | ☐ |
| 개인정보/약관 링크 | 앱 내 접근 가능 | 실제 URL/내용 유효 | ☐ |
| 계정 삭제 동선 | 설정→삭제→재로그인 | 개인정보 처리 정책과 일치 | ☐ |
| 크래시 체크 | 실제 안드로이드 기기 2대 이상 | 치명 크래시 0건 | ☐ |

## 3) 핵심 시나리오 (수동 QA)

아래 8개는 최소 회귀 테스트 세트입니다.

1. 온보딩 완료 → 홈 진입
2. 회원가입/로그인 → 재시작 후 세션 유지
3. 기록 작성(텍스트) → 홈/기록 목록 반영
4. 기록 작성(이미지) → 업로드/조회/삭제
5. 기록 공개 ON → 공감숲 목록 노출
6. 공감숲에서 공감/취소 + 신고 + 본인글 삭제
7. 네트워크 끊김 상태에서 재시도 UX
8. 계정 삭제 후 재로그인/데이터 접근 확인

## 4) Play Console 등록 준비물

- 앱 이름/짧은 설명/상세 설명 (한글 기준 문안 확정)
- 대표 아이콘 512x512, feature graphic, 스크린샷
- 개인정보처리방침 URL
- 타깃 연령/콘텐츠 등급 설문 답변
- 데이터 보안(수집/처리) 설문 답변
- 테스트 트랙(Internal/Closed) 우선 배포 계획

---

## 5) 생성형 AI 고지 권장

현재 온보딩 하단에 다음 문구를 노출:

`이 서비스는 생성형 AI를 활용합니다`

추가 권장:

- 개인정보처리방침/이용약관에 AI 활용 목적, 처리 범위, 사용자 통제 방법 명시
- Play Console "앱 기능 설명"에도 동일 취지로 간단히 고지

---

## 6) 지금 프로젝트 기준 권장 출시 전략

- 1단계: Internal Testing (팀 내부)
- 2단계: Closed Testing (소수 사용자 20~50명)
- 3단계: Open Testing 또는 정식 출시

정식 출시는 최소 3~7일 이상 크래시/치명 이슈 모니터링 후 진행을 권장합니다.

---

## 7) 자동 검증 다시 돌리기

- 로컬: `npm run verify` (lint → typecheck → format:check → test:ci → build)
- Cursor에서: **"자동 검증 실행해줘"** 또는 **"체크리스트 자동 검증 돌려줘"**라고 요청하면 위 표 항목들을 실행해 결과를 갱신해 줄 수 있습니다.
