# 감정기록 모아보기 개선 계획 (목록 보기 + 전부 삭제)

> 추후 구현용 정리 문서. 당장 진행하지 않음.

---

## 1. 목표

- **감정기록 모아보기** 모달에서:
  1. 내가 기록한 감정을 **리스트 형태로 조회**할 수 있게 한다.
  2. **감정기록 전부 삭제** 기능을 추가하고, 삭제 시 **꽃/성장 데이터도 함께 초기화**하여 일관성을 유지한다.

---

## 2. UI 설계

### 2.1 모달 구조 (최종안)

| 구역 | 내용 |
|------|------|
| **상단** | 제목 "감정기록 모아보기" + 요약 문구 (총 N개, 공개/비공개 개수) |
| **목록 영역** | 스크롤 가능한 리스트 (날짜, 감정 이모지/라벨, 내용 요약) + "더 보기" |
| **내려받기** | [JSON 내려받기] [CSV 내려받기] (기존 유지) |
| **안내 문구** | "삭제 전에는 내려받기로 백업할 수 있어요." (선택) |
| **전체 삭제** | [감정기록 전부 삭제하기] 버튼 (하단, 위험 액션 스타일) |

- 기록이 **0개일 때**: "전부 삭제" 버튼은 **비활성화** 또는 **숨김** 처리.

### 2.2 목록 영역 상세

- **표시 항목**: `emotion_date`(또는 created_at), 감정 라벨/이모지, `content` 일부(한 줄, 말줄임 가능).
- **정렬**: 최신순 (이미 `emotions` 조회 시 최신순 사용 중이면 그대로 활용).
- **초기 개수**: 예) 최근 30건 표시 후 **"더 보기"**로 추가 로드 (또는 스크롤 시 무한 스크롤).
- **스타일**: 목록 영역에 `max-height` + `overflow-y: auto` 적용해 모달이 과도하게 길어지지 않도록.

## 3. 전부 삭제 설계

### 3.1 안전 장치 (필수)

1. **1차 확인 모달**
   - 문구 예:  
     "모든 감정 기록을 삭제할까요? 이 작업은 되돌릴 수 없어요. 필요하면 먼저 'JSON 내려받기'로 백업해 주세요."
   - 버튼: [취소] / [삭제하기] (삭제하기는 강조/위험 스타일).

2. **2차 확인 (권장)**
   - 옵션 A: "정말 삭제하려면 '삭제'라고 입력해 주세요" + 입력 필드.
   - 옵션 B: 체크박스 "모든 기록이 삭제됨을 이해했어요".
   - 둘 중 하나 적용 시 실수 클릭 방지에 유리.

### 3.2 실행 흐름

1. 사용자가 "감정기록 전부 삭제하기" 클릭.
2. 1차 확인 모달 표시 (백업 안내 포함) → [삭제하기] 선택 시.
3. (선택) 2차 확인(입력 또는 체크).
4. **백엔드 순서**:
   - (선택) 연동 데이터 정리: 공감숲 게시·스토리지 이미지 등 정책에 따라 처리.
   - **emotions** 전부 삭제 (`user_id` 기준).
   - **flowers** 진행 중 꽃 초기화 (아래 4장 참고).
5. 성공 시: 토스트 "모든 감정 기록이 삭제되었어요.", 모달 닫기, 홈/마이페이지 데이터 refetch.

## 4. 백엔드 (쿼리·로직)

### 4.1 기존 쿼리

- **변경 없음.** 단건 삭제, `updateFlowerGrowth`, `ensureFlowerRow` 등 기존 로직 그대로 유지.

### 4.2 추가할 쿼리/함수

| 구분 | 내용 |
|------|------|
| **감정 전부 삭제** | `supabase.from('emotions').delete().eq('user_id', userId)` 1회 호출. |
| **꽃 초기화** | 진행 중 꽃(`is_bloomed = false`) 1건에 대해 `growth_percent: 0`, `flower_type: 'seed'` 등으로 UPDATE. |

**꽃 초기화 구현 옵션**

- **A)** 기존 `ensureFlowerRow`로 진행 중 꽃 row 조회 → `.update(payload).eq('id', flowerRow.id)`.
- **B)** `.update(payload).eq('user_id', userId).eq('is_bloomed', false)` (유저당 진행 중 꽃 1개 전제).

개화된 꽃(`is_bloomed = true`)은 **삭제하지 않는** 방향 권장 (앨범/히스토리 유지).  
초기화 대상은 **진행 중 꽃만**으로 한정.

### 4.3 RLS 확인

- **emotions**: `DELETE` 정책에 `user_id = auth.uid()` 조건 있으면 bulk delete 추가 쿼리만으로 가능. 기존 단건 삭제가 동작 중이면 보통 동일 조건으로 허용됨.
- **flowers**: `UPDATE` 정책에 `user_id = auth.uid()` 있으면 초기화용 update 별도 수정 없이 사용 가능.

→ **스키마/RLS 재작업이 아니라, 새 클라이언트 쿼리 2개 추가 + 기존 RLS 확인**이면 됨.

### 4.4 연동 데이터 정책 (추후 결정)

- **community_posts**: emotions와 연동된 게시가 있다면, 감정 전부 삭제 시 해당 게시도 삭제할지 여부 결정.
- **스토리지**: emotions의 `image_url`에 해당하는 파일 삭제 여부 결정 (삭제 시 스토리지 정리 로직 추가).

## 5. 구현 순서 제안

| 단계 | 작업 |
|------|------|
| 1 | 감정기록 모아보기 모달에 **목록 영역** 추가 (날짜·감정·내용 요약, 스크롤, 더 보기). |
| 2 | **전부 삭제** 백엔드: emotions bulk delete + flowers 진행 중 꽃 초기화 함수 추가. |
| 3 | **전부 삭제** UI: 버튼 + 1차(필수)·2차(권장) 확인 모달 + 삭제 후 refetch/토스트. |
| 4 | 기록 0개일 때 전부 삭제 버튼 비활성화/숨김, 필요 시 연동 데이터(공감숲·이미지) 정리 정책 반영. |
